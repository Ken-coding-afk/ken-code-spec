# 大改动计划

本目录只用于大改动。普通功能修改和局部缺陷修复使用对话中的简略方案即可。

## 触发条件

满足任意一项时创建正式文档：

- 跨越 3 个及以上逻辑模块或服务。
- 修改架构、核心数据流或模块边界。
- 修改公共 API、数据库、认证、权限、构建或部署方式。
- 涉及迁移、兼容、灰度或回滚。
- 大规模重构，可能改变既有行为。
- 用户明确要求方案文档、设计文档或执行计划。

## 命名

```text
YYYY-MM-DD-主题-design.md
YYYY-MM-DD-主题-implementation.md
```

主题使用简短的英文小写连字符形式，例如：

```text
2026-07-14-template-analysis-design.md
2026-07-14-template-analysis-implementation.md
```

## 使用方式

1. 分别复制 `_design-template.md` 和 `_implementation-template.md`。
2. 填写真实信息，删除不适用的提示文字，不编造未知事实。
3. 两份文档一起提交用户确认，确认前不要开始大规模编码。
4. 执行中只在阶段边界更新清单和偏差，不记录逐文件流水账。
5. 完成后回填真实测试命令、结果、未验证项和遗留风险。
