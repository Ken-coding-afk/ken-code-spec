# 大改动计划

本目录用于大改动的单一计划文档。普通改动不在这里创建文档，只在对话中说明修改方式并等待确认。

## 触发条件

满足任意一项时创建 plan 文档：

- 跨越 3 个及以上逻辑模块或服务。
- 修改架构、核心数据流或模块边界。
- 修改公共 API、数据库、认证、权限、构建或部署方式。
- 涉及迁移、兼容、灰度或回滚。
- 大规模重构，可能改变既有行为。
- 用户明确要求计划文档。

## 命名

```text
YYYY-MM-DD-主题-plan.md
```

主题使用简短的英文小写连字符形式，例如：

```text
2026-07-14-template-analysis-plan.md
```

## 使用方式

1. 如果存在会实质影响方案的未决问题，先向用户提问，等待决定后再生成最终 plan。
2. 复制 `_plan-template.md`，填写真实信息，删除不适用的提示文字，不编造未知事实。
3. 初稿通常控制在 1～3 页，提交用户确认后再开始实施。
4. 执行中只在阶段边界更新清单；如果方案发生实质变化，暂停执行并重新确认。
5. 完成后在同一文档中回填实际偏差、测试结果、未验证项和遗留风险。

状态依次使用：`草稿` → `已确认` → `执行中` → `已完成`。
